# install MUST run with --no-build-isolation — confirmed on a real pod:
# `xtcocotools`'s legacy setup.py imports numpy directly at build time but

# this venv alone does NOT fix it: pip's *default* behavior builds each
# sdist in its own isolated build env that doesn't see this venv's packages
# at all, so the isolated build subprocess still has no numpy even though
# the outer venv does. --no-build-isolation makes pip build against this
# venv directly instead (same reason detectron2 itself needs the flag,
# per facebookresearch/sam-3d-body's own INSTALL.md) — but it means every
# package below must have its own build-time deps already satisfied by
# what's already installed (numpy/cython/torch), which is why those come
# first as a separate command.

# torch/CUDA version: pin torch to whatever CUDA toolkit is actually
# installed on the machine (check `/usr/local/cuda-*/bin/nvcc --version` —
# it may not be on PATH), not just torch>=X unpinned. Confirmed on a real
# pod: an unpinned `pip install torch` resolved to a cu130 build while the
# system toolkit was 12.8, and detectron2's build (below) fails outright
# with a CUDA version mismatch in that state — even though the same
# mismatched torch imports and runs fine on its own; the crash only shows
# up once you try to compile a native extension against it. Use
# `--index-url https://download.pytorch.org/whl/cu128` (or whatever
# matches) explicitly, and reinstall torch+torchvision *together* in one
# pip command if you ever need to change torch's version after
# torchvision is already installed — reinstalling torch alone leaves
# torchvision's compiled extensions ABI-mismatched against the new torch
# (`RuntimeError: operator torchvision::nms does not exist`), also hit and
# fixed on a real pod.
#
# --no-build-isolation --no-deps per INSTALL.md — install everything above
# first, then this separately:
#   pip install 'git+https://github.com/facebookresearch/detectron2.git@a1ce2f9' --no-build-isolation --no-deps
#
# The actual sam-3d-body package: confirmed on a real pod that it is NOT
# pip-installable at all (`pip install git+...sam-3d-body.git` fails with
# "does not appear to be a Python project: neither 'setup.py' nor
# 'pyproject.toml' found") — INSTALL.md/the official notebook both assume
# you `sys.path.insert` a cloned checkout instead. See
# pipeline/envs/sam3dbody/setup.sh, which clones it to
# /workspace/venv_sam3dbody_vendor and adds a .pth file — same pattern as
# seedvr2's vendored ComfyUI-SeedVR2_VideoUpscaler.
#
# MoGe (github.com/microsoft/MoGe) — sam3d_body's FOV / focal-length
# estimator (pipeline/steps/sam3d_body.py, fov_estimator="moge2"; INSTALL.md
# step 5). NOT listed above because it is installed separately, PINNED to
# b942f00 (the last MoGe-2 commit) and --no-deps: `main` is now MoGe-3 whose
# deps include a nvcc-built extension, gradio>=6, and a git package named
# `pipeline` that would shadow this repo's own package in this venv. Only
# moge.model.v2 is on the FOVEstimator path and it needs just utils3d (also
# pinned, --no-deps) plus torch/scipy/numpy. Done by setup.sh and the
# Dockerfile's venv_sam3dbody layer. Set fov_estimator="" to skip it and
# fall back to the focal = sqrt(h**2 + w**2) guess.
